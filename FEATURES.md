# Функции экспортёра: что было и что добавилось

Хронология версий: **2.2** (базовая, из вашего прежнего репозитория) → **2.3** → **2.3.1**
(обе — прошлая сессия) → **2.3.2** (экспорт архива) → **2.4.0** (текущая: скорость,
один архив на два формата).
Файл **2.3.3** добавлялся в этой сессии и удалён по вашей просьбе.

---

## 1. Что было изначально (v2.2)

Панель экспорта Tampermonkey-скрипта на arena.ai / lmarena.ai / chat.lmsys.org:

| Функция | Как работает |
|---|---|
| Кнопка **Export** у края экрана | Открывает панель с настройками экспорта |
| **Current chat** → Download JSON / Download TXT | Выгрузка открытого чата в одном из двух форматов |
| **Conversation list** → Fetch list | Загрузка списка чатов через `/api/history/unified` (по 20, с курсором) |
| Мультивыбор (чекбоксы), Select all, Clear | Отметить чаты и видеть «N selected» |
| **Select agent** | Кнопка «выбрать только агентные чаты» |
| **Export selected JSON / TXT** | Пакетная выгрузка выбранного в один ZIP |
| ZIP-упаковка (fflate) | Сжатие архива без манифеста |
| Определение типа чата | Обычный (`/api/evaluation/<id>`) или Agent Mode (`/agent/<id>`, разбор Next.js flight-данных) |
| TXT для обычных чатов | Заголовок, роли, время, `[reasoning]`, вложения |
| TXT для агентных чатов | `[tool: имя]`, часть `input` (query/url/command/path/prompt/questions/content/old_text/new_text), часть `output` (status, exit_code, до **8** результатов web_search без описаний, stdout, stderr), `data-tool-results` |
| Локализация | Английский + китайский (zh-CN), переключение языка |
| Служебный API в консоли | `window.__arenaChatExport(id, format, type)` |
| Защита пагинации | Лимит страниц `HISTORY_PAGE_GUARD = 200` |

**Чего не было:** манифеста в ZIP, полных тел `fetch_page`/`read_file` в TXT, описаний
результатов поиска, меток усечения, пометок «в архиве», выбора охвата списка.

## 2. Изменения прошлой сессии (v2.3 → v2.3.1)

### v2.3 — «TXT без потерь» + манифест

| Что добавлено | Детали |
|---|---|
| Полные тела инструментов в TXT | `fetch_page` (весь записанный текст), `read_file` (содержимое), все результаты `web_search` **с описаниями**, все поля `input`/`output` (`appendToolIO`) |
| Метки неполноты | Предупреждения об усечении на стороне Arena (`stdout_truncated`, `stderr_truncated`, прочее) |
| `manifest.json` в ZIP | `selectedCount`, `successCount`, `failedCount`, списки `successfulExports`/`failedExports`, `warnings` |
| ZIP всегда | Архив собирается даже при выборе одного чата; если всё упало — ZIP только с манифестом |
| Предупреждение о вложениях | Файлы не скачиваются, ссылки могут истечь |

### v2.3.1 — чистота интерфейса и явные ограничения

| Что сделано | Детали |
|---|---|
| Удалена кнопка **Select agent** | Ненужная: тип чата определяется автоматически |
| Удалена китайская локализация | Остались только английские строки |
| Явные уведомления в TXT | «есть ещё чанки `fetch_page`», «`read_file` вернул выдержку», «изображение: только метаданные, байтов нет», «инструмент вернул ошибку» |
| Таймстемпы сообщений | Строка `Time` в TXT для агентных чатов |
| Сжатие ZIP | `zipSync(..., { level: 6 })` — DEFLATE |

## 3. Экспорт архива (v2.3.2)

### Главное: архивные чаты без разархивирования

В 2.3.1 список запрашивался с жёстко зашитым `includeArchived=false`, поэтому архивные
чаты не попадали в пакетную выгрузку. У `/api/history/unified` есть параметры
`includeArchived` и `archivedOnly`, а записи содержат `archivedAt`.

| Что добавлено | Детали |
|---|---|
| Селектор **Scope** | `Active + archived` (по умолчанию) / `Active only` / `Archived only`; «Archived only» шлёт `archivedOnly=true` — как фильтр «Archived» на сайте |
| Пометка архива в списке | Значок `archived <дата>` у архивных чатов |
| Счётчики | `Loaded N conversations (X archived)`, `N selected (X archived)` |
| `archivedAt` в выгрузке | Верхний уровень JSON, строка `Archived : ...` в TXT, `archivedCount`/`listScope`/`selectedItems` в `manifest.json`, `archivedAt` в успешных и неуспешных записях |
| Кнопка **Save list JSON** | Выгрузка загруженного списка (id, тип, заголовок, даты, флаг архива) для сверки |
| Страховка пагинации | Прерывание при повторе курсора (`seenCursors`) |
| `applyHistoryMetadata` | Если API не вернул `archivedAt`, значение подставляется из списка; то же для пустого заголовка |

### Что добавлялось и убрано по вашей просьбе

- v2.3.3 (режим сверки с сохранённым списком + выгрузка «только недостающих» чатов) —
  **удалён**, 2.3.2 снова единственная текущая версия.

## 4. Скорость и один архив на два формата (v2.4.0 — текущая)

Файл: `Arena.ai - LMSYS Arena Chat Exporter-2.4.0.user.js`. Версия 2.3.2 осталась на месте
без изменений — если что-то не понравится, достаточно переустановить её.

### Почему стало быстрее

Раньше чаты качались строго по одному: запрос → пауза 160 мс → следующий. Медиана времени
на чат в ваших партиях — 1,5–1,8 с, из которых почти всё — сеть, а не обработка (локальная
сборка JSON+TXT для чата на 26 МБ занимает ~0,4 с). Поэтому ускорение даёт только
параллельность.

| Что сделано | Детали |
|---|---|
| Параллельная загрузка | Пул воркеров, селектор **Parallel** (1/2/**3**/4/6/8, по умолчанию 3), разброс старта до 80 мс, фиксированная пауза 160 мс убрана |
| Таймаут и повторы | Таймаут запроса 120 с (`AbortController`), до 3 попыток при 408/425/429/500/502/503/504 и при сетевых ошибках, пауза 0,8–3 с с джиттером. Параметр можно переопределить: `window.__arenaChatExportTimeoutMs = 15000` |
| JSON + TXT за один проход | Кнопки **Download JSON + TXT** (текущий чат), **Export selected JSON + TXT**, **Export everything**; каждый чат скачивается **один раз**, а в ZIP кладутся оба файла. Раньше два формата означали две загрузки |
| Стриминговый ZIP | `Zip`/`ZipDeflate` из fflate: каждый файл сжимается сразу, в памяти не держатся одновременно все несжатые тексты и архив (fallback на `zipSync`, если потокового API нет) |
| fflate внутри скрипта | `@require` с CDN убран — библиотека (33 КБ, MIT) вшита в файл, ZIP собирается даже при недоступном CDN |
| Меньше копий в памяти | Убрано глубокое клонирование агентной записи (`JSON.parse(JSON.stringify(...))`) при зачистке токена: копия делается только там, где есть что зачищать |
| Список по 50 | `/api/history/unified` умеет `limit` до 50; теперь список грузится вдвое-втрое меньшим числом запросов |
| Кнопка **Export everything** | Один клик: загрузить весь список (с учётом Scope) → выгрузить все чаты в JSON + TXT одним ZIP, с манифестом, прогрессом и ETA |
| Прогресс | «N/M, ~Xm Ys left, failed: K» — оценка по фактическому темпу |

### Замер (одинаковая работа, одинаковая задержка сети)

`node tests/bench-batch.mjs --chats 48 --latency 700` — 48 чатов, 700 мс на запрос:

| Версия | Формат | Parallel | Время | На чат | Запросов к API чатов | Параллельно |
|---|---|---|---|---|---|---|
| 2.3.2 | JSON | 1 | 41,4 с | 863 мс | 51 | 1 |
| **2.4.0** | JSON | 3 | **11,9 с** | 248 мс | 49 | 3 |
| **2.4.0** | JSON + TXT | 3 | **12,0 с** | 251 мс | 49 | 3 |

Итог: **3,4×** на этой конфигурации, и второй формат теперь бесплатен по времени (раньше —
вторая полная загрузка).

Второй замер, ближе к вашим реальным партиям (`--chats 60 --latency 1500`):

| Версия | Формат | Parallel | Время на 60 чатов | На чат |
|---|---|---|---|---|
| 2.3.2 | JSON | 1 | 99,7 с | 1662 мс |
| **2.4.0** | JSON | 3 | **30,8 с** | 514 мс |
| **2.4.0** | JSON + TXT | 3 | **30,9 с** | 515 мс |

То есть **3,2×** при задержке 1,5 с на запрос, и весь ваш архив (~244 беседы, из них 41
агентная) должен собираться примерно за 6–7 минут вместо ~20–30. Если хочется быстрее —
Parallel 4–6.

### Что осталось прежним

- Форматы JSON и TXT **не менялись** — 2.4.0 выдаёт те же файлы, что 2.3.2 (проверено
  автотестами на обоих форматах), плюс `formats`/`concurrency` в манифесте.
- Архивные чаты, Scope, пометки, `archivedAt`, Save list JSON — как в 2.3.2.
- Предупреждения о вложениях и о неполных выводах инструментов — на месте.

### Чего сознательно не делали

- Быстрый аудит «только по шапке» — не нужен: текущий аудит JSON-партии занимает 0,8 с,
  TXT-партии (86 МБ) — 2,5 с.
- Минификация, смена уровня сжатия, переписывание парсера — выигрыш не стоит риска.
